# Common Review Standards (Shared Logic)

本文件定義了所有 Reviewer (Code, Docs, Cross) 都必須遵守的通用審查標準。
Reviewer 應專注於各自的領域，但底層邏輯必須一致。

## 1. Linus 核心原則檢查 (The Linus Check)

所有產出物都必須通過以下過濾器：

*   **[ ] Simplicity**: 是否有更簡單的寫法？(如果看不懂，就是爛)。
*   **[ ] Necessity**: 這段程式碼/文字真的有必要嗎？(刪除比增加更好)。
*   **[ ] Future-Proof**: 是否為未來留了活路？(但不要過度設計)。

## 2. 程式碼審查清單 (For Code Reviewer)

*   **[ ] 資料結構**: 是否使用了正確的資料結構？(e.g., Map vs List)。
*   **[ ] 命名**: 變數名稱是否精確反映其內容？(拒絕 `data`, `temp`, `obj`)。
*   **[ ] 函式長度**: 是否超過 20 行？縮排是否超過 3 層？
*   **[ ] 錯誤處理**: 是否吞掉了錯誤？錯誤訊息是否清楚？
*   **[ ] 測試覆蓋**: 是否有對應的測試？測試是否包含邊界情境？

## 3. 文件審查清單 (For Docs Reviewer)

*   **[ ] 清晰度**: 是否有模糊的形容詞？(e.g., "適當的", "快速的" -> 改為具體數值)。
*   **[ ] 一致性**: 術語是否統一？
*   **[ ] 完整性**: 是否遺漏了關鍵章節？
*   **[ ] 可執行性**: 步驟是否具體到可以被執行？

## 4. 評分標準 (Scoring)

請依據以下標準給予評分 (1-10)：

*   **10分 (God-tier)**: 完美，優雅，教科書等級。
*   **8-9分 (Excellent)**: 符合所有標準，無明顯缺點。
*   **6-7分 (Pass)**: 功能正常，但有小瑕疵 (命名、註解)。
*   **4-5分 (Mediocre)**: 能跑，但很醜，難以維護。 -> **退回重做**
*   **< 4分 (Garbage)**: 邏輯錯誤，架構混亂。 -> **退回重做**
